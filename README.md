# 🌷 يومي — منظمي الشخصي

منظم شخصي (Personal Organizer) بواجهة عربية RTL يجمع في مكان واحد: نية اليوم،
الصلاة، المهام، الدراسة، العادات، الأهداف، وأثر الخير اليومي — مبني حسب خريطة
التطبيق المرفقة في هذا المستودع.

## البنية

- **البداية / التعريف بالمستخدمة**: ترحيب، الاسم، الاهتمامات، اختيار 3–5 عادات،
  واختيار لون التطبيق (5 مظاهر پاستيل).
- **يومي** (الشاشة الرئيسية): نية اليوم، صلاتي (٥ صلوات)، أهم مهامي، عاداتي،
  وبطاقة "أثري اليوم"، بالإضافة لبطاقة مراجعة المساء تظهر تلقائيًا مساءً.
- **دراستي**: ملخص الأسبوع (مهام / اختبارات / جلسات مذاكرة) وموادي، وعند فتح
  مادة: مهامها واختباراتها وجلسات مذاكرتها.
- **أهدافي**: أهداف بخطوات وشريط تقدم.
- **عاداتي**: تتبع أسبوعي (٧ أيام) لكل عادة بدون رسائل "فشل" — تشجيع دائمًا.
- **أثري**: إضافة أثر سريع (وسوم جاهزة أو نص حر) وسجل "آثاري الجميلة"، ويمكن
  الوصول له من "يومي" ومن "مساحتي" (وليس تبويبًا مستقلًا في الشريط السفلي).
- **مساحتي**: الملف الشخصي — الاسم، اللون، ستيكراتي، اختصارات للعادات/الأهداف/الأثر،
  الحساب والمزامنة (اختياري، انظر أدناه)، ملاحظاتي، وإعدادات التطبيق (بما
  فيها إعادة الضبط).

كل البيانات تُحفظ محليًا على الجهاز أولًا (`localStorage`) — يعمل التطبيق كاملًا
بلا حساب أو اتصال بالإنترنت. الحساب والمزامنة السحابية ميزة **اختيارية** فوق
هذا الأساس (تفصيل أدناه)، لا تُستبدله.

## التقنيات

- React 19 + TypeScript
- Vite
- Tailwind CSS v4
- خط Tajawal (Google Fonts) لدعم عربي مريح
- Supabase (اختياري) — للحساب والمزامنة السحابية فقط

## التشغيل محليًا

```bash
npm install
npm run dev       # تشغيل بيئة التطوير
npm run build     # بناء نسخة الإنتاج
npm run lint      # فحص الكود
```

## النشر (رابط دائم مجاني عبر GitHub Pages)

المستودع يحتوي على `.github/workflows/deploy-pages.yml` يبني وينشر التطبيق
تلقائيًا على GitHub Pages مع كل push لفرع `claude/personal-organizer-app-map-y8rrdh`.

**خطوة واحدة فقط عليكِ فعلها يدويًا (لمرة واحدة)** — إنشاء "موقع Pages" نفسه
أمر لا يقدر عليه الورك‌فلو تلقائيًا مهما كانت صلاحياته، فهو يحتاج صلاحية مالك
المستودع تحديدًا:

1. من صفحة المستودع على GitHub: **Settings ← Pages**.
2. تحت "Build and deployment" اختاري **Source: GitHub Actions**.
3. من تبويب **Actions**، شغّلي ورك‌فلو "Deploy to GitHub Pages" يدويًا عبر
   "Run workflow" (أو ادفعي أي تعديل جديد فيشتغل تلقائيًا).

بعدها سيظهر الرابط الدائم في نفس صفحة Settings ← Pages، عادة بالشكل:
`https://<اسم-الحساب>.github.io/YOMI/`

هذا الرابط:
- **مجاني ودائم** ويتحدّث تلقائيًا مع كل تعديل تدفعينه للفرع.
- **لا يحتاج أي حساب أو تسجيل دخول** لأي طالبة — تفتحه من المتصفح مباشرة.
- بيانات كل طالبة (نيتها، مهامها، عاداتها، أثرها...) تُحفظ في متصفحها هي فقط
  ولا تُشارك مع أحد.
- قابل للتثبيت كأيقونة حقيقية على الشاشة الرئيسية (Add to Home Screen) بفضل
  ملف الـ Web App Manifest المرفق — يظهر باسم "يومي" وأيقونة الزهرة 🌷.

## الحساب والمزامنة السحابية (اختياري)

ميزة **"☁️ الحساب والمزامنة"** في مساحتي تتيح لأي طالبة تسجيل دخول ببريدها
الإلكتروني وكلمة مرور، لأخذ نسخة احتياطية من بياناتها في السحابة، وتزامنها
بين أكثر من جهاز — بما في ذلك استعادة كلمة المرور ذاتيًا إن نسيتها. هذه
الميزة **مخفاة تلقائيًا** ما لم تُفعّليها — التطبيق يعمل محليًا بشكل طبيعي
تمامًا بدونها.

### التفعيل (لمرة واحدة)

1. أنشئي مشروعًا مجانيًا على [supabase.com](https://supabase.com) إن لم يكن
   لديكِ واحد.
2. من **SQL Editor** في مشروعك، شغّلي محتوى الملف
   [`supabase/schema.sql`](supabase/schema.sql) (يُنشئ جدول `profiles` مع
   قواعد Row Level Security بحيث لا تقدر أي طالبة على رؤية بيانات طالبة أخرى).
3. من **Authentication → URL Configuration**: أضيفي رابط تطبيقك المنشور
   (مثال: `https://digital0impact.github.io/YOMI/**`) في **Redirect URLs**،
   وأيضًا كـ **Site URL**. ضروري لتعمل روابط "نسيت كلمة المرور" بشكل صحيح.
4. من **Authentication → Providers → Email**: اختياري تعطيل **"Confirm
   email"** لتسجل كل طالبة دخولها فور إنشاء الحساب بلا خطوة تأكيد بريد؛
   تركها مفعّلة أكثر أمانًا لكنه يضيف خطوة (فتح البريد والنقر على رابط
   التأكيد) قبل أول دخول.
5. من **Project Settings → API**، انسخي **Project URL** و **anon public key**.
6. أضيفيهما بالمستودع كـ Secrets (**Settings → Secrets and variables →
   Actions → New repository secret**):
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
7. ادفعي أي تعديل جديد (أو شغّلي الورك‌فلو يدويًا) ليُعاد بناء التطبيق ومعه
   الميزة الجديدة.

للتشغيل محليًا (`npm run dev`) بنفس الميزة مفعّلة: انسخي `.env.example` إلى
`.env.local` وعبّئي القيمتين نفسيهما (هذا الملف مُتجاهَل من git تلقائيًا)،
وأضيفي أيضًا `http://localhost:5173/**` إلى Redirect URLs في نفس الإعداد.

### كيف تعمل تقنيًا

- كل طالبة تسجّل ببريدها الإلكتروني وكلمة مرور عبر نظام المصادقة القياسي في
  Supabase (تجزئة كلمات المرور، جلسات آمنة، واستعادة كلمة مرور ذاتية عبر
  البريد).
- بياناتها (نفس ما يُحفظ في `localStorage`) تُرفع كـ JSON في عمود
  `app_state`، وتُزامَن تلقائيًا بضع ثوانٍ بعد كل تغيير طالما هي مسجّلة دخول.
- عند تسجيل الدخول من جهاز فيه بيانات محلية مختلفة عن النسخة السحابية، يُخيَّر
  بين النسختين صراحةً (لا يُستبدل شيء تلقائيًا وبصمت).
- `localStorage` يبقى دائمًا هو المصدر الأول والفوري — السحابة نسخة احتياطية
  فوقه، وليست بديلًا عنه.
- إن أرادت طالبة أو معلمة إعادة تعيين كلمة مرور يدويًا بدل البريد: **لوحة
  Supabase → Authentication → Users**، اختيار الحساب، وإعادة التعيين من هناك.
